CoA-Text2OWL : Apprentissage d'Ontologies
par Chaîne d'Agents IA

Un framework multi-agents basé sur les LLMs pour améliorer la génération automatique d'ontologies OWL à partir de textes non structurés, en combinant des agents travailleurs parallèles et un agent gestionnaire synthétiseur.

AuteursH. Ghanem · S. Jabbar · C. Cruz
LaboratoireICB UMR 6303 CNRS · Université Bourgogne Europe
ConférenceKES 2025 — Procedia Computer Science
FinancementANR TRACES · ANR LAMAE
Résumé

L'apprentissage d'ontologies réinventé par les agents IA

L'apprentissage d'ontologies à partir de textes non structurés reste un défi complexe. CoA-Text2OWL introduit un framework multi-agents exploitant les LLMs dans une architecture Chain-of-Agents pour améliorer la génération d'ontologies. Contrairement aux approches mono-LLM, le système distribue la tâche entre plusieurs agents travailleurs — chacun traitant un segment du texte — tandis qu'un agent gestionnaire synthétise leurs sorties en une ontologie cohérente. Validé sur le domaine de la pizza et sur les données urbaines du projet TRACES à Genève, CoA-Text2OWL démontre des améliorations significatives dans l'extraction des propriétés d'objet et la complétude ontologique.

Architecture

Trois modules complémentaires

Le framework CoA-Text2OWL s'articule autour de trois composants principaux qui travaillent en séquence pour transformer un document PDF en ontologie OWL formelle.

Schéma d'architecture CoA-Text2OWL
Input PDF → Chunks 120 mots → Worker Agents (CU1…CUn) → Manager Agent → Ontology Serialization → Fichier .ttl

Fig. 1 — Framework CoA-Text2OWL : du document PDF à l'ontologie OWL sérialisée en Turtle

1

Input Processing Module

Extraction du texte via PyMuPDF et segmentation en chunks de ~150 mots, préservant la cohérence sémantique tout en optimisant le traitement parallèle par les agents.

2

Chain-of-Agents Core

Agents travailleurs parallèles (Mistral-7B) traitant chaque chunk et générant des sous-ontologies partielles en Turtle. Un agent gestionnaire intègre et déduplique les résultats.

3

Ontology Output Module

Sérialisation finale de l'ontologie unifiée au format Turtle (.ttl), conforme aux standards RDF/OWL du W3C, prête pour le raisonnement et l'inférence.

Prompts agents

Des instructions précisément calibrées

Chaque rôle d'agent est guidé par un prompt spécifique. Les agents travailleurs se concentrent sur l'extraction, l'agent gestionnaire sur l'intégration et la cohérence.

Prompt 1 — Agent Travailleur
You are a helpful assistant in building an ontology. You are fluent in the W3C Semantic Web stack and RDF, RDFS, and OWL languages. Use the given text to construct an OWL ontology in the Turtle format. Use this namespace: http://example.org/example#. Return only the turtle file. Extract all the possible classes and subclasses.
Prompt 2 — Agent Gestionnaire
You are an ontology learning expert, and your goal is to integrate some sub-ontologies into a coherent ontology while ensuring no redundancy. Your response should be structured, modular, and ready for further reasoning and inference.

Limites & Défis

Des pistes d'amélioration identifiées

Malgré ses avancées, CoA-Text2OWL fait face à quatre défis structurels qui orientent la feuille de route de recherche.

1

Perte des structures hiérarchiques

La réduction des relations RDFS subClassOf indique que le traitement multi-agents ne préserve pas pleinement les dépendances hiérarchiques, en raison de la segmentation et des lacunes de communication inter-agents.

2

Couverture conceptuelle limitée

Bien que CoA-Text2OWL surpasse le baseline pour les propriétés d'objet, il capture significativement moins de classes que l'ontologie de référence. Élargir la couverture sans augmenter le bruit reste un problème ouvert.

3

Stochasticité des LLMs

Malgré temperature=0, des variations mineures ont été observées entre les runs. Des couches de vérification structurées pourraient stabiliser les sorties et garantir la reproductibilité.

4

Scalabilité sur domaines complexes

L'applicabilité à grande échelle reste une question ouverte. De futures optimisations devront explorer l'efficacité de traitement et la rétention mémoire pour élargir le champ d'application.

Perspectives

Vers un framework modulaire spécialisé

Les prochaines étapes de recherche visent à transformer CoA-Text2OWL en un pipeline multi-étapes avec des agents dédiés à chaque sous-tâche de l'apprentissage ontologique.

Agents spécialisés par tâcheChaque worker Wᵢ suivi d'un worker Wⱼ dédié : extraction de propriétés d'objet, identification des hiérarchies, validation des mappings classe-à-classe.
Pipeline multi-étapes completImpliquer le CoA à chaque phase : extraction de termes, classification de concepts, identification de relations, construction de hiérarchies, génération d'axiomes.
Coordination dynamique des agentsMécanismes adaptatifs d'orchestration pour gérer des domaines larges et complexes, avec rétention mémoire entre les agents et vérification croisée.
